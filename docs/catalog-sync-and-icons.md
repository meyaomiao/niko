# 0.2.10 模型目录同步与厂商图标修复

## 实况与问题

本轮核对 [MomoToken 公开定价目录](https://momotoken.win/api/pricing)时，响应包含 329 个模型、19 个厂商，目录版本为 `a42d372ccf0b5dd13ecf71203521f9d2`。其中 242 个模型有发布日期，87 个没有日期。以上为检查时的站点数据，不代表每个账号都能使用全部模型；可用范围仍取决于账号分组。

旧客户端从这个接口只读取厂商表、分组描述与倍率，丢弃了完整模型表，实际展示仍依赖登录引导接口中的模型和价格。模型页也只在进入或手动点击时载入目录。若两个服务端响应更新不同步，新上架型号和新的发布元数据可能无法及时显示。

此外，当定价目录明确没有可用模型时，旧逻辑会回退到旧分组中的模型列表，可能重新显示下架或无权使用的型号。原有厂商图标大多是字母占位，服务端的 `Gemini.Color`、`Claude.Color` 等标识没有接入显示组件。

## 模型同步行为

- 官方站点以当前成功获取的完整公开目录确定模型集合，更新价格、发布日期及厂商归属；当前账号的余额、单位、授权分组和专属倍率仍来自鉴权接口。
- 成功的空目录、明确为空的分组权限和无账号权限的模型都不会回退旧列表。新目录中已不存在的型号会移除。
- 第三方中转站继续使用其自己的目录、价格与账号倍率，不请求或套用 MomoToken 的公开价格。兼容旧接口未提供 `enable_groups` 的格式。
- 可见窗口每分钟同步，返回窗口时同步，支持手动强制刷新；隐藏窗口不轮询，焦点与可见性事件合并，并发响应和离页后的旧结果不会覆盖当前页面。
- 公开目录不可用时，保留同账号上次成功目录并按最新账号权限重新过滤；余额仍可独立更新。页面明确显示同步失败及上次目录时间，首次失败则说明当前使用账号目录。
- 同步保留仍有效的模型和分组选择。失效选择会清空并提示重选，不自动换成另一个型号，也不自动改写已接入客户端。权限变化会停止旧测速，申领密钥后、写入配置前还会重新检查当前目录权限。
- 新有效发布日期会覆盖旧元数据；空值或错误日期不阻断有效的回退值。没有日期的型号不补造发布日期。

## 图标覆盖与来源

[品牌图标组件](../src/components/VendorIcon.tsx)使用本地资源，优先解析已知服务端图标标识，再按公司或产品别名回退。比如 `Google + Gemini.Color` 显示 Gemini，`Anthropic + Claude.Color` 显示 Claude。未知标识不直接变成远程图片地址。

19 个厂商中，18 个已对应到可核实来源的品牌图标。302.AI、NanoGPT、SAP 使用厂商网站资源；其它图标采用固定版本的 LobeHub 品牌图标集，并保留其来源和 MIT 许可。具体文件、来源与处理方式见 [图标来源记录](../public/vendor-icons/CREDITS.md)。这些社区维护的品牌图标不宣称由各厂商直接提供。

QiHang 的厂商条目未提供图标、网站或说明。外部模型目录指向的网站当前使用 QuanHex 品牌，尚不能确认它与该条目的对应关系，因此显示明确的“暂无可核实品牌图标”占位。

## 验证方式

- 使用当前完整公开响应走实际解析与合并函数，并给合成账号提供响应中全部分组权限，329 个模型全部保留；不使用真实账号或密钥。
- 页面回归执行真实 hooks 与事件处理，网络、存储和 IPC 全部使用内存夹具。覆盖新增型号、权限撤销、旧请求返回、选择保留、分组测速取消和配置写入前重验。
- 图标回归覆盖 19 厂商映射、服务端标识优先、别名、未知回退、本地资源和来源；另核对了浅色、深色和 18px 显示，72 张预览图片全部成功加载。
- [Mac / Windows 双端验证](../scripts/dual-verify.sh)的类型检查、构建及各自 188 项测试全部通过。同步脚本同时关闭 macOS AppleDouble 元数据打包，避免 Windows 收到额外的 `._` 伴随文件。提交后还需通过独立 CI。

本轮不重新安装或启动用户已卸载的 Niko，也不修改 ChatGPT 等已接入客户端的配置。
